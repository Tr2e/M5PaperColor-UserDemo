# Tr2e / PaperColor 独立日历固件

独立ESP-IDF项目，固定400×600竖屏。与根目录Demo分别构建，未链接其应用、HAL、照片、云推送、Web相册或USB磁盘模块。共享的仅为现有M5GFX、M5Unified、M5PM1硬件驱动。当前源码版本 **0.2.0**，已同步新编排、排版及 A 版落款。**本次只生成内置内容包并做主机验证，没有运行 ESP-IDF 构建、没有生成新可烧录固件、没有烧录实机。** `release/` 中仍是此前的 0.1.1，不能用旧压缩包验收本次效果。唤醒、电流与纸屏效果仍待实测。

## 日常行为

1. 开机先根据RX8130的本地日期显示日历；不先等待网络。
2. 只有手动开机/关机重启（含顶部电源键单击），以及15天维护周期到期的RTC唤醒，才尝试联网校时。普通午夜唤醒不初始化Wi-Fi。看门狗/棕断等恢复启动不额外联网。
3. 校时使用已有Wi-Fi凭据，STA模式，无后台重连；连接最多12秒，SNTP最多18秒。完成后销毁SNTP并停止、释放Wi-Fi。
4. 校时成功才写RTC并读回验证。UTC明确转换为UTC+8；如日期跨日或跨年，重新显示正确日期。
5. 设置下一公历日00:00的RTC闹钟，读回确认分钟、小时、日、日匹配模式和中断使能；关闭屏幕电源、SD及RGB电源，再由PMIC断电。USB供电等情况下如未成功切断主电源，则退回ESP深睡定时唤醒。

**顶部电源键单击**：由M5PM1唤醒/重启设备，先显示本地日历，再尝试联网校时，校验日期并在需要时重绘，最后重新休眠。即使尚未到15天，也允许这次手动校时；手动按键与RTC闹钟同时触发时以按键为准。看门狗、棕断等异常复位忽略残留按键标志，避免异常重启反复联网。按键由电源芯片处理，无常驻按键轮询任务。参见[官方电源键说明](https://docs.m5stack.com/en/core/PaperColor)。

午夜前10秒内不抢着断电：等午夜经过，校验画面，再设置下一次闹钟，避免闹钟在断电过程中触发而漏掉一天。UTC+8、跨月、跨年及闰年都采用实际日期计算，睡眠间隔不用于推算显示日期。

维护周期以自然日计。尝试校时前就保存下次尝试日期（15天后）；失败不会更改RTC或最后成功校时日期，也不会变成每天联网重试。用户手动开机仍可提前重试。错过维护日后，在下一次允许的RTC唤醒补做维护。若RTC失效且日期不可判断，不在自动唤醒中擅自联网；需要手动开机恢复校时。

RGB没有状态动画或后台任务。仅手动开机、休眠前各给约80ms的低亮度提示；每日自动唤醒完全静默。扬声器、麦克风、IMU、5V外供、SD卡与SD检测均不使用。低电压时跳过刷新和无线操作。实际续航不能由编译或模拟结果推算，需要测量电池端休眠电流。

## 页眉与小字

星期放在月日文字右侧10px处，随日期实际宽度移动；节气与星期左对齐。星期、年月、农历使用14px Noto Sans CJK SC子集，出处使用12px同款黑体。作者/职业保持13px宋体，外文姓名保持11px宋体，落款采用已确认的 **A「书末署名」**：15px常规宋体 `Tr2e`，字下短线，使用与样稿相同的黑白位图。全部在1位黑白栅格上渲染，不依赖设备联网下载字体。

正文最后一行实际字形底部与下横线保持 **16px**；标题字形底部至正文上横线保持 **20px**。数字在剩余空间内调整高度及上下留白。作者/职业、外文名及出处的字体、位置和行距均沿用样稿。2027全年365张参考渲染结果与批准PNG逐像素一致。

## 首次联网与配置

启动时优先读取`tr2e`命名空间的Wi-Fi凭据；如不存在，可一次性导入原设备`papercolor`命名空间中的`wifi_ssid`/`wifi_pass`。不依赖原Demo程序运行，也不修改其设置。

更换网络：**按住A键开机并保持至设置画面出现**。这是手动配置入口，设备不会因网络失败而自动开热点。屏幕显示临时AP名称、随机密码与`http://192.168.4.1`；连入后填写家中2.4GHz Wi-Fi。设置成功或180秒超时后关闭AP，回到日历/休眠流程。网络密码不输出到日志。

RTC电压丢失标志VLF或非法日期不会被当作可信时间；失败时保留日历/显示简短设置提示。配置期间使用设备端小网页，没有照片、云端、图库或第三方脚本。

## 内容与年度稳定性

- 全部内容、字形、农历信息、年度安排内置于`main/assets/calendar.pack`，约2.43MB（2,435,508字节），无SD卡或年度下载要求。
- 支持2026—2099年，共74年、27,028天；范围由RX8130两位年份能力约束。
- 每年选句组和完整标题均不重复。去重沿用规范化文本与已识别近似句分组；仍受原始OCR质量限制。
- 普通日期的选句至少冷却5年，标题至少冷却2年；专题池按最久未使用优先轮换，优先保证主题合适。
- 实际验证：相邻两年最多15个选句组重合，至少95.8%不同；2026→2027为零重合。有限内容库不能保证无限年完全不重复。
- 2026年沿用已批准的计划，2027年逐日固定为 `artifacts/tr2e_calendar_2027_editorial_v2_1/2027.json`；2028—2099年采用新版规则结合历史生成固定安排。设备按RTC查表，不用开机随机抽句；断电、重启、校时回退都不会重新洗牌。
- 年度来源安排指纹在NVS保存；同一年刷入改变该年来源安排的固件会被拒绝展示，避免升级后悄悄重复。仅改字形/版式不会改变该指纹。不要擦除NVS来绕过本年保护。
- 夏至、5月8日、11月11日只参与内部选句；不在页眉显示私人生日/纪念日。正常节气照常显示。落款固定为A版`Tr2e`字下短线。
- 年初分为元旦与迎新；12/27—12/31分为回望、宽慰、回望、期待。春节按实际春节日分成归家、团聚、舒展与启程；除夕、腊八、元宵、端午、七夕、中秋、重阳按农历安排，同日节气合并显示。没有强制“宜”等于积极，也没有整段13天全选励志句。
- 喜庆及私人日期邻日使用专题候选，检查冲突、失落、心理困境与成人亲密等语境；作者生日、忌日只给经过通读的适配候选加分，不能挤掉私人日期与节日优先级。
- 继续保留标题和选句原配；使用2027人工通读标注、排除清单和月度视角，分散邻近作者、话题和沉思语气。2028年后普通日期还会用到明确标为旧库标签的内容，并非宣称74年全部逐句人工审定；原始OCR和出处仍有既有资料的局限。

新资源采用 `TR2EPK03` 格式，包含实际使用的38档数字高度和A版位图字形。旧资源和新解码器不混用。`tools/tr2e_calendar/production_planner.py`、`production_layout.py` 与 `build_device_pack.py` 是设备资源生成入口；旧 `planner.py`、`render.py` 保留用于已冻结的历史研究与样稿复现。

这是将编辑规则**预编译到固件**，并非设备每天运行Python或联网生成内容。更新规则/内容需要重新构建资源和固件；正常换年不需要。

## 构建、验证、烧录

仅生成内容包及主机验证（本次已执行，不编译ESP32固件）：

```sh
python3 tools/tr2e_calendar/build_device_pack.py --cache /tmp/tr2e-editorial-v3-plans
python3 calendar_firmware/tests/verify_pack.py
python3 -m unittest discover -s tools/tr2e_calendar -p 'test_*.py' -v
```

`verify_pack.py`只用本机clang++编译可移植C++渲染/日期测试程序到临时目录，不运行ESP-IDF，不生成或覆盖固件bin。源码/资源同步记录见`tests/source-sync-verification.json`；`tests/build-verification.json`是旧0.1.1编译记录。

今后明确需要可烧录固件时，再从仓库根目录运行：

```sh
./calendar_firmware/idf.sh build
python3 calendar_firmware/tests/verify_pack.py
python3 -m unittest discover -s tools/tr2e_calendar -p 'test_*.py' -v
```

Python验证需要Pillow和本机clang++。ESP-IDF使用本机5.5.x工具链和已安装的硬件依赖；可设置`PAPERCOLOR_IDF_PATH`。不下载原Demo的应用依赖。

需要重新生成全部年度与字形时：

```sh
python3 tools/tr2e_calendar/build_device_pack.py
```

请保留已投入使用的年度安排。资源构建时会检查每年去重与相邻年份5%重复上限，超出即失败；首次整库生成需几分钟。缓存位于`/tmp/tr2e-device-plans`，只用于构建，设备不依赖它。

接上PaperColor并确认端口后：

```sh
./calendar_firmware/idf.sh -p /dev/cu.usbmodemXXXX flash
./calendar_firmware/idf.sh -p /dev/cu.usbmodemXXXX monitor
```

后续生成新版发布包后，也可使用`release`目录中的可烧录压缩包。**当前目录中的0.1.1压缩包仍是旧效果，本次未更新它。**只写`0x0`引导程序、`0x8000`分区表、`0x10000`应用；保留原NVS和`0xA00000`照片存储区域，**不使用erase_flash**。不要运行根目录Demo的flash命令。

压缩包解压后，在其目录运行`bash flash.sh /dev/cu.usbmodemXXXX`。该脚本使用`python3 -m esptool`；也可设置`TR2E_PYTHON`为已有ESP-IDF Python环境的可执行文件。不含自动擦除或烧录后自动修改网络设置的操作。

## 验证范围

`tests/verification.json`保存新包全74年的去重、专题池、语境与普通日5年/2年冷却检查。C++实际渲染器逐页对照2026与2027全年，并补充闰日、末年和所有数字高度；本次739页全部像素一致，最大差异为0；字形接触处的少量抗锯齿叠加已通过资源中的稀疏黑色像素补偿，未改变字体或行位置。2027 Python参考图另外与批准的365张样稿做零差异比较。日期边界、2026→2027、闰日、计划指纹、15天无线窗口、失败后不每日重试、资源损坏拒绝加载另有C++测试。

仍需实机验收：电池供电下PMIC断电、RX8130凌晨唤醒、USB下深睡备用路径、Wi-Fi/SNTP失败超时、校时跨午夜、RTC掉电、首次网络迁移、RGB静默、真实休眠电流。硬件未连接，因此这些不能标为已通过。

硬件/协议依据：[Epson RX8130CE应用手册](https://download.epsondevice.com/td/pdf/app/RX8130CE_en.pdf)、[ESP-IDF 5.5系统时间](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/system/system_time.html)。字形子集授权保留在`tools/tr2e_calendar/assets/*OFL.txt`与发布包中。

# 堆叠笔触优化试验

日期：2026-09-14

后续版本：九图回归后，原型已加入细节参考、内容尺度缩放与有预算的结构补画。最新设计、验证结果与限制见 [结构保留优化记录](papercolor_stacked_brush_optimization.md)。下文保留首次笔触形状实验记录，所述笔触数不代表当前版本。

状态：主机视觉试验。`render_stacked_ppm.cpp` 不在固件 CMake 源码列表内；设备仍使用已提交的原版油画核心。试验目标是参考用户提供的静物画中不透明色块叠压的笔触组织，当前仅用仓库的花田风景图验证。

## 问题与修改

| 上一版问题 | 本轮修改 | 预期作用 |
|---|---|---|
| 所有笔触都是切角多边形 | 压力变化、轻微弯曲、非对称起收笔、窄边缘抗锯齿 | 保留实色笔触主体，减少几何贴片外观 |
| 逐像素颜色门限截断笔触 | 绘制前按四个方向的颜色差收缩笔触长宽 | 保持笔触连贯，允许后续细笔修正边界 |
| 平坦区方向逐笔随机 | 平坦区使用低频方向变化；轮廓处使用局部结构张量 | 降低杂乱方向，增强笔触沿形体组织的感觉 |
| 候选笔触按旧画布一次选完 | 打乱候选位置后，每笔读取最新画布并重新评估区域误差 | 避免已经补好的区域继续被细笔覆盖 |
| 最近邻参考图留下 3px 方格 | 双线性采样，24px 网格上的平滑底色 | 减少底层像素块对笔触形状的干扰 |

主笔触不透明度约 93%–99%，仅轮廓及收笔部位降低覆盖；沿笔触方向的细微颜料变化不添加浮雕阴影。四层半径为 26/15/9/5，并逐笔改变尺寸。后续层根据区域平均误差和最大误差决定是否补画。

## 复现

```bash
python3 tools/oil_paint_lab/render_stacked_preview.py \
  main/apps/local_photo_slideshow/images/imaged004.png \
  artifacts/oil_paint_preview/brush-v3 \
  --rotate-clockwise 90 --sanitize
```

脚本将照片顺时针旋转到横屏，与 Canvas rotation=1 的 backing 方向一致，输出 600×400 RGB565 画面。生成原图、试验结果、并排对比和 `render.json`，后者保存源码/输入 SHA-256、实际笔触数量、sanitizer 与确定性检查结果。

如本地保留上一轮预览，可增加：

```text
--baseline artifacts/oil_paint_preview/landscape-stacked.png
```

脚本编译实际 C++ 试验实现，连续运行两次并比较输出字节；`--sanitize` 启用 ASan/UBSan。Pillow 负责输入准备及图片排版，笔触由 C++ 算法绘制。

## 已验证与限制

花田样本实际绘制 173/421/556/462 笔，共 1612 笔；上一轮 330/566/993/1320 笔，共 3209 笔。约减少一半落笔，不代表耗时同比下降，因为新笔刷的逐像素计算更复杂。主机 `-Wall -Wextra -Werror`、ASan/UBSan 和字节级重复性检查通过。

对比可见：细碎切角块减少，平坦天空保留较大色面，花田与石头的方向更连续。部分云边仍有印章感；当前试验不具有物体语义，也不保证所有题材都改善。

设备接入前需继续评估：

1. 将逐像素噪声、覆盖计算预计算为笔刷掩码或行数据，评估定点实现；当前代码含浮点运算和动态 vector。
2. 恢复生产核心的工作区接口、照片矩形/stride 契约、调度检查点与资源上界验证。当前 CLI 处理整帧，不提供这些固件契约。
3. 沿用已有控制器的照片 generation、快照恢复和互斥机制，另行增加新核心测试。
4. 通过 M5GFX 的六色转换与实体屏检查笔触是否仍可辨认，再决定固件默认参数。

# 16/20固定白色目标的配比对照（2026-09-10）

## 状态与依据

用户已明确人工校验首页缩略图/Logo修复通过，并要求继续校色。首页UiWithPhotos修复保留，照片校色仍以IMG_9952对应算法为基线。本轮不要求重复首页验收。

IMG_9952的16洋红仍灰红紫、20青色仍偏绿灰。IMG_9942已经证明单独减白有变沉的代价，且未解决色相；因此不再加大减白。此前IMG_9936的原生混色网格用于提示变化方向，但它采用另一种点阵排列，不能直接当照片配方。本轮用实际PhotoBalanced扩散生成局部配比对照，保持目标白色/黑色份额，检查彩色相对比例是否还有改善空间。

## 对照定义

列顺序 **A / B / C / A**，两端A逐像素相同，用于识别照明/位置差异。

- A：当前已保留的照片输出。
- B：红或绿在“彩色部分”中的份额减少6.25个百分点，转给蓝。
- C：红或绿在“彩色部分”中的份额增加6.25个百分点，从蓝中转出。
- 白/黑目标不变。不是把总像素的6.25%改色，也不是进一步减白。±6.25个百分点是探索区间，不是拟合出的最优值；C更红或更绿不自动代表准确。

| 行 | 内容 | A / B / C 的作用 |
|---|---|---|
| 1 | 16洋红 | 对比红蓝比例，寻找偏蓝灰与偏红褐之间的折中 |
| 2 | 20青色 | 对比绿蓝比例，检查少绿是否更接近青色、加绿是否进一步偏绿 |
| 3 | 17浅紫 | 四列均使用基线A，固定参照 |
| 4 | 10蓝青边缘 | 四列均使用基线A，固定参照 |
| 5 | 19纯蓝 | 四列均使用基线A，固定参照 |
| 6 | 22灰96 | 四列均使用基线A，固定参照 |

顶部六原生锚点保持原生直送。该图不是完整24色回归；固定参照也不能证明一个尚未实现的广域算法通过回归。

## 如何生成，及为何不直接写进照片算法

`generate_secondary_ratio_abc_chart.py` 在临时目录复制真实照片实现，仅在投影、配比和减白之后、Q4量化之前插入 `secondary_ratio_probe.h` 的诊断函数。该函数只作用于源RGB `(255,0,255)` 和 `(0,255,255)`，沿红蓝/绿蓝线转移彩色份额。B/C使用原算法所有后续量化和扩散流程，先渲染完整400×600源图，再裁剪原生码。

**这两个精确输入的临时扰动只是实验探针，不是可用于任意照片的连续策略。** `secondary_ratio_probe.h` 在ESP_PLATFORM下会编译报错，固件的正式照片算法没有此调用；设备仅展示预生成诊断素材，A键回首页时仍用用户已经通过的正常算法和首页修复。

四个控制行全部从A完整帧复制，避免B/C在其他位置传播的扩散误差改变参照纹理。16/20则分别来自三个完整帧，不做裁剪后重新抖动、不改原始照片、不调整手机白平衡。原生码最后一次性送屏。

## 实拍顺序与下一步

先检查两端A与四个固定控制行是否一致，10/19是否仍无规则边缘点列；再分别比较16和20的A/B/C色相、明暗、白雾感及颗粒。两个目标允许不同结论，不预设同一列同时最好。如果仅是更红/更绿、或更沉而非更接近源色，应保留A。

只有实拍支持明确方向后，才设计对一般照片平滑衰减的正式候选，并复查09/17/18、10/19、暖色、灰阶、全RGB565连续性和首页策略一致性。不将此次两点探针直接合入正式算法。

配置 `tools/color_lab/secondary-ratio-abc-sdkconfig.defaults`；默认关闭的新诊断启动开关与其他图表互斥。构建、镜像及烧录状态见TODO和 `.cache/firmware/secondary-ratio-abc-v1/manifest.json`。只允许USB及同连接MAC均为 `44:1B:F6:C1:34:10` 的PaperColor，应用0x10000；stopwatch不打开，照片/设置分区不写入。

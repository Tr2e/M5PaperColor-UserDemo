# 人像低色度暖色 A/B/C

IMG_9970 与 Kodak 04 原图对照后，脸颊、额头、牙齿和胸颈的暖色在实屏上呈黄绿/橄榄感。源图统计显示，脸颊约 78%、额头约 91%、胸颈约 84% 的采样像素落在红+黄候选扇区；现有 IMG_9963 暖色比例修正主要服务高饱和橙色，对这些较低饱和暖色介入很弱。项链源图本身带青色，不能把它的全部青绿表现当成同一问题。

本诊断只比较一条轴。A 是 IMG_9970 已烧录的完整颜色策略与 Burkes；B 在连续的低色度、偏亮暖色窗口中，最多把红黄总彩色覆盖的 1/16 从黄色转给红色；C 的上限为 1/8。黑色、白色、红黄总覆盖和扩散核保持。高饱和橙红、纯红、暗暖色、中性、绿/青/蓝/紫扇区均由平滑窗口保护。

屏幕按三列显示 A/B/C，五行依次为眼睛与上半脸、脸颊与嘴、颈胸、红帽保护和粉色布景保护。每个裁剪来自一张完整 400×600 Burkes 渲染，不能独立重置误差；三列只改变上述黄色到红色比例。预览是标称颜料 RGB，仅用于检查构图与字节组成，物理色相必须看屏幕。

离线结果符合预期。上半脸黄色码 A/B/C 为 921/859/816、红色码为 1018/1069/1120；脸颊与嘴为黄 691/623/540、红 1336/1408/1494；颈胸为黄 713/634/581、红 1028/1094/1161。红帽三列几乎不变。粉色布景存在较小变化，作为副作用保护项观察。完整帧 A/B/C SHA-256 为 `cd577513400bd7b3103c814d48ec9de008acfcfc75e14b70fa9e301c0ba04dd9`、`03635d682e97a2e0519a385f84c25f39077cd05c3d994c82958e50eb8fc8828b`、`81a5a94ef2ba6d121d022d054915463c8679f4fa93e43a90a6951a5442b23f6d`。72,000 字节载荷 SHA-256 为 `35d22fbb7941ab03928100780c5d270816945977e9ffdbaa58ef93406e7de2ae`。

验收时先比较 B/C 是否比 A 减少脸和胸颈的黄绿感，并保留自然明暗；再看牙齿是否变粉、嘴唇是否糊成一片。红帽应保持近似不变，粉色布景不能明显发红。若 B 已改善且 C 过红，选择 B；若两者均无改善或牙齿/布景副作用更明显，则否决这条轴。

独立应用 `.cache/firmware/portrait-warm-abc/paper_color.bin` 为 3,314,112 字节，SHA-256 `8fd9e2069e83a9f19095fe58921bed7f73c95678e572ee9fc7076628d94a5a51`，checksum `93` 与 validation hash 有效。USB 序列号、位置和芯片 MAC 均确认属于 Color `44:1B:F6:C1:34:10` 后，只向 `/dev/cu.usbmodem83301` 的应用地址 `0x10000` 写入；27.4 秒完成且设备端数据哈希验证通过。stopwatch 未枚举、未访问，其他分区未写入。等待实屏 A/B/C 照片。

# 11/12绿系分轴A/B/C对照

基于IMG_9958阶段基线。11黄绿看起来偏黄，12青绿偏沉且白点明显；这两个问题不能用一个参数解释。本图只做诊断，不修改正式照片算法。

四列为A/B/C/A，两端A用于识别位置与照明差异。所有裁块都由真实PhotoBalanced实现先渲染完整400×600源表，再从完整扩散上下文裁出88×50原生码；设备不二次量化或抖动。

11不含白/黑目标，B实际黄2214/绿1914，C为黄2734/绿1394。12配比B为白161/蓝1151/绿2816，C为白160/蓝652/绿3316；1个白码差来自Q4与扩散。12白量B为白74/蓝921/绿3133，C为白0/蓝932/绿3196，黑始终0。减白会同时变暗并改变点阵，不预设白点越少越准确。

临时函数只识别RGB565展开后的11输入(156,255,0)和12输入(49,154,99)，并按编译时诊断模式改变其中一个轴；`ESP_PLATFORM`下直接编译失败，不能进入设备照片策略。七个模式各自完整渲染两次且结果确定；A帧SHA-256为IMG_9958基线 `61b7a31855ef42f920eb37fdadd4b0f6925995c1a2be5fc6c16fad42edc6b2f1`。控制行三种裁剪逐字节相同。

载荷39,600字节，SHA-256 `cb819954b55337db2b4c1b778241fb070eba8b03c32a539185dd20f8e9141b36`。ASan/UBSan采样器覆盖合法整帧、空/短载荷、非法半字节与越界，112,320个采样像素与独立组图一致。PNG仅为布局与名义颜料预览，不是面板模拟。

实拍顺序：先核对两端A和10/20/17控制；再看11的B是否增加绿色但仍保持黄绿亮度；12配比行判断少绿/多蓝是否更像青绿；最后单独看白量行的亮度、白点与网纹取舍。11和12允许选不同方向，也允许全部保留A。只有方向明确后才设计对一般照片连续衰减的正式候选，并做全RGB565、渐变、完整表和首页回归。

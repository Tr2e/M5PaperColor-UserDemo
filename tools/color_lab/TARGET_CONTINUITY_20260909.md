## 可复现方法

```sh
python3 tools/color_lab/audit_target_continuity.py
```

依赖 C++17 编译器、Git 和 Pillow。工具先比较运行颜色源码、头文件和 LUT
与提交 `21b0370` 的内容，若不同则拒绝把结果标为基准。临时编译的
`probe_targets.cpp` 直接包含运行实现，调用实际 RGB565 解码、候选集合、
补偿和 Q4 目标投影函数，没有复制一套映射规则，也没有添加固件诊断接口。

输出：

- `artifacts/color_calibration/target-continuity-21b0370.json`：源码哈希、
  全色域扫描、渐变摘要、人像采样和均匀色块的原生色码比例。
- `artifacts/color_calibration/target-continuity-ramps-21b0370.csv`：8 条渐变，
  每条 256 个输入、实际候选 mask 和投影目标，可独立作图。

扫描覆盖 65,536 个 RGB565 颜色和 191,488 条相邻格点边。
相邻格点只改变一个量化通道，解码后变化 4/5 或 8/9 级。
距离均为 **gamma 编码的标称 RGB 欧氏距离**，不是 Delta-E，
不是物理屏幕色差。阈值 30 仅用于筛选大跳变，没有可见性判定含义。

同时计算一个诊断对照：只跳过旧源色补偿，仍用同一候选色域、单颜料白色
约束和 Q4 舍入。它用于归因，没有形成或启用替代固件。

## 发现一：旧补偿存在明显的边界跳变

| 格点边分类 | 数量 | 现行目标最大跳变 | 跳过补偿的最大跳变 | 现行距离 >30 数量 |
| --- | ---: | ---: | ---: | ---: |
| 候选集合、补偿启用状态均相同 | 175545 | 12.94 | 12.94 | 0 |
| 候选集合变化（可能同时改变补偿） | 11755 | 78.84 | 28.86 | 1438 |
| 候选集合相同、补偿启用状态变化 | 4188 | 83.04 | 9.00 | 1341 |

因此这次扫描中全部 2,779 条超过 30 的边都与旧补偿有关，不能把
“候选集合变化”一组全部归咎于色域本身。即使跳过补偿，候选集合切换仍有
最高 28.86 的目标步长，连续性问题并没有由此全部解决。

最强的可复现实例：

- 输入 `(123,73,255)` → `(132,73,255)`，只改变 R 的一个 RGB565 格点。
- 两侧均允许黑、白、红、蓝。后一侧触发 `2*R >= B` 的紫蓝旧补偿，
  其补偿输入从原值直接变成 `(224,73,231)`。
- 目标从 `(115.0625,79.4375,250.5625)` 跳到
  `(171.6875,115.5,201.6875)`，距离 **83.04**；跳过补偿时距离 **6.35**。
- 实际 FS 渲染均匀 400×600 图，在去除 32 像素边缘后，蓝色比例
  **89.56% → 45.13%**，白色 **8.68% → 33.97%**，红色 **1.76% → 20.90%**。
  输出平均标称 RGB 与各自目标距离小于 0.06，证明跳变传到了颜料比例。

这是代码层面的缺陷证据，仍不是移除全部补偿能改善实屏的证据。旧补偿曾用于
压制蓝颜料视觉优势，整体删除可能改变已验收的混色表现。

## 发现二：该补偿不是人像肤色问题的直接解释

对 Kodak 04 **原始 512×768** 像素逐一量化为 RGB565；未缩放，不能宣称
与 M5 PNG 解码器缩放后的 400×600 帧逐像素一致。矩形按原图肉眼选取，
不是语义分割，也不把全部矩形像素认定为皮肤。

| 原图区域（左上/右下，右下不含） | 像素数 | 触发旧源色补偿 |
| --- | ---: | ---: |
| 整图 `(0,0)-(512,768)` | 393216 | 0.1124% |
| 脸颊 `(140,365)-(190,435)` | 3500 | 0% |
| 肩部 `(350,610)-(445,700)` | 8550 | 0% |
| 帽子 `(130,60)-(380,155)` | 23750 | 0% |
| 粉紫布料 `(410,450)-(490,535)` | 6800 | 0% |

脸颊样本中 79.4% 进入黑/白/红/黄集合，20.6% 进入黑/白/红集合。
最常见量化颜色 `(123,97,82)` 的均匀色块产生约 **48.48% 黑、30.41% 白、
8.02% 黄、13.10% 红**，平均标称 RGB 与目标距离仅 0.032。
这说明在当前数学模型中，抖动确实接近所要求的平均颜色；它既不能证明
这些颜料覆盖率在实屏上能还原肤色，也不能衡量高对比网点对人像细节的干扰。

物理颜料与标称 sRGB 混色的差异、肤色候选集合的约束、网点空间纹理仍需分别
验证。现在没有理由把肤色发灰简单归因于旧补偿，也不宜先添加肤色经验系数。

## 验证与下一步

- 既有默认配置 host 回归、H5 源图预览回归通过。
- **验收配置**（单颜料白色约束开启）的 host 回归及 ASan/UBSan 通过，
  含两种滤波器、灰阶、原生色码、长运行残差和内存边界。
- 10 个 Python LUT/指标解析测试通过。
- 新诊断验证完整色域的打包/解码往返、扫描边数，以及均匀色块实际输出
  与目标的平均值一致性。host 耗时没有被用作 ESP 性能结论。

后续应分成两项独立实验：

1. 紫蓝补偿边界：只研究平滑启用补偿的候选，保留远离边界的既有行为，
   做连续渐变、紫/洋红/青色与整图 A/B，再决定是否上设备。
2. 人像肤色：在同一光线下配对拍摄原生颜料/已知比例混色与人像，
   优先加入上述脸颊附近的黑白红黄覆盖率参考。先确认混色比例的物理表现，
   再讨论纹理。手机照片只作相对比较，不能拟合为绝对校色 profile。

拍摄保持相同光源、距离、角度，锁定曝光和白平衡，保留完整屏幕与白边；
避免反光和自动滤镜。只有可重复的数据才用于决定新模型。性能记录绑定照片
仍在原 TODO 中待做，本轮没有改变指标接口或扩大运行代码范围。

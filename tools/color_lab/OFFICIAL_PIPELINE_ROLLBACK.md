# 图片算法回退与校色研究封存（2026-09-14）

## 当前决策与边界

生产固件回到仓库内 M5GFX 的 `M5Canvas::pushSprite()` → `Panel_ED2208` 颜色转换及面板驱动。首页、两种图片浏览器、引导页和二维码都直接提交 Canvas；不再编译或调用 `papercolor_lut_display.cpp`、实验 LUT、照片抖动器、色表/人像诊断图，也不嵌入校色 LUT、参考照片或诊断载荷。`main/Kconfig.projbuild` 不再提供实验开关。独立分支 `codex/color-calibration-research`（检查点 `9fbea2b`）从原有阶段提交延续，保存实验源码、生成器、报告、图表、原构建入口和配置；此分支只用于研究，不属于生产固件构建。

这是**图片算法回退**，不是回退其他已验收功能。首页构图、缩略图缩放/裁剪、Logo 素材、日期/音频局部刷新、照片库和设置的代码保留。2026-09-10 的首页颜色修复原本确实依赖 `UiWithPhotos` 实验模式；现在不保留该实现，而是让首页缩略图、Logo 和浏览器都由同一个官方转换路径处理。普通首页与普通照片浏览均使用 `epd_quality`。`imageN` 快速照片及首页局部刷新沿用各自的 `epd_fastest` 特例，因此必须单独检查；缩略图和全屏图尺寸不同，不能要求逐像素网点一致。原先“首页修复已人工通过”只适用于旧实验固件，不能自动视为本次回退后的实机验收。

显示指标中的 `PaperColorPipeline` 行随实验管线移除；通用 `DisplayMetrics` 保留。仓库内 M5GFX 组件与 `Panel_ED2208` 未修改。当前此前烧录的是人像暖色 A/B/C 第一版诊断应用；A/B/C/A 第二版仅构建、未烧录（见 `TODO_COLOR_CALIBRATION.md` 和 `IMG_9971_REVIEW.md`）。在新应用完成安全烧录前，屏幕状态不能作为回退结果。

## 本次回退的验证

1. 使用全新 ESP-IDF 构建目录和配置，从默认 `sdkconfig.defaults` 构建。检查配置不再包含 `CONFIG_PAPERCOLOR_*`，构建清单和最终 ELF 中没有实验 LUT、照片抖动及诊断图对象/符号，镜像校验有效；保留可复现镜像哈希。
2. 审查所有生产显示提交路径：首页、本地照片、EzData 照片、引导和二维码均调用官方 `pushSprite()`；启动不再进入任何校色图。正常照片和首页的 EPD 模式一致，局部/快速路径例外明确。
3. **尚待实机**：只识别 Color 的 USB 序列号/芯片 MAC `44:1B:F6:C1:34:10` 和物理位置 `8-3.3`；不要打开或烧录 stopwatch `44:1B:F6:C1:8A:00`（曾为 `8-3.4`）。仅写应用分区 `0x10000`，不写 bootloader、分区表、照片存储和 NVS。确认下载模式后执行，记录镜像 SHA、端口身份、设备端哈希校验与重启结果。
4. 在 Color 上验收：正常启动进入首页；同一张原图在首页缩略图与图片浏览器的主要色相一致，Logo 没有与图片明显不同的异常偏色；文字/线框和日期/音频局部刷新正常。另看人像脸/红帽/背景是否回到可接受的官方基线，以及照片和设置是否保留。用固定光源、固定手机白平衡/曝光、相同角度各拍一张；拍摄本身不能替代直接观察。

构建实绩：ESP-IDF 5.5 独立目录 `/private/tmp/papercolor-official-rollback-build` 成功完成链接与应用大小检查。冻结镜像 `.cache/firmware/official-pipeline-rollback/paper_color.bin` 为 3,188,240 字节，SHA-256 `edcacf01f092f52767099e2499e1f5e1b766706214cd2f86e49f58f335bf0cc8`，image checksum `9c`、validation hash 有效。相应配置、生产源码快照及复现命令见同目录 `manifest.json`。新配置无 `CONFIG_PAPERCOLOR_*`；构建清单无实验源文件/载荷，最终 ELF 无实验 LUT、抖动和诊断入口符号；`git diff --check` 通过。**尚未烧录，尚未实机验收**，不能把编译通过写作图片观感通过。

## 后续研究目标与任务

目标是**在六色面板的物理色域内，让常见图片观感至少不劣于官方基线，并以可测的色彩改善为收益**。肤色层次、红帽与背景的分离、灰阶清洁和细节边界是保护项；不能为了 24 色表局部更接近源图而接受“揉成一片”的人像。不可达的源色只要求落在可信的可达近似，不追求逐像素 sRGB 复原。

1. 冻结官方基线：记录本次固件 SHA、原始图片文件哈希、显示模式、24 色表、灰阶、人像 Kodak 04 和至少两张其他肤色/高纹理照片的原始输入及实拍。量化固定环境下重复拍摄和左右位置造成的波动；IMG_9971 已证明横向位置偏差可与候选差异同量级。先得到噪声界限，再谈微调。
2. 离线分解问题：分别测量目标色投影、实际面板可达色、抖动纹理和 RGB565/缩放误差。用原生颜料片或经过测量的面板输出建立可达色参照；不要从单张手机照片直接反推全域 LUT。保留 A/B/C/A 等同屏重复对照，但旧 A/B/C/A 第二版不自动成为下一次烧录任务。
3. 候选必须带单一假设、固定参数、预先指定的受益区域与保护区域。先在主机上做全 RGB565/边界/确定性/内存与完整测试图检查，再使用与官方固件同一图片、同一缩放和同一 `epd_quality` 路径进行盲评。人像局部若需要优化，应先证实独立缺陷，再限制作用区域和边缘外溢，不能靠不断叠加全域补偿掩盖问题。
4. 只有候选达到下列门槛，才考虑重新接入固件；仍以独立实验构建和应用分区烧录验证。未过门槛时维持官方算法，记录失败原因后停止该方向，不继续无限次“调一点、拍一张”。

## 重新启用算法的验收标准

- **可复现**：固定输入、配置和代码可生成相同输出；完整 RGB565 域没有非法色码、新的不连续边界、缓冲区越界或不可控内存增长；回退开关能恢复官方逐字节路径。
- **颜色收益**：在固定环境、重复 A/B/A 或 A/B/B/A 对照中，预先指定的色块改善方向超过位置/拍摄波动；24 色表的原生色、灰阶和已选保护色无可见退步。若要报告色差数字，须先完成面板测量与色域可达性校准，不能把手机照片的 RGB 差直接当作面板 ΔE。
- **照片保护**：固定人像组中，脸、头发/织物、红帽和背景能清楚分层；不能出现比官方基线更明显的脏灰、互相污染、长链网纹或细节抹除。至少两位观察者在打乱 A/B 标记后分别判断，且结果在重复拍摄中稳定；若主观意见分歧或只有色表受益，候选不通过。
- **产品回归**：首页缩略图/Logo 与图片浏览器颜色策略一致；本地/EzData/快速照片、局部刷新、启动、照片与设置存储均正常。候选构建在性能和内存上不超过实际设备预算，并有一键恢复官方算法的构建/烧录记录。

每轮只针对一个预先定义的问题做一次主机筛选和一组可复现的同屏实测。结果不超过测量噪声、照片保护未通过或发现新污染时，结论为“暂不采用”；修改假设后才开启新一轮。官方基线是产品默认状态，不再把实验固件当成连续校色的默认入口。
